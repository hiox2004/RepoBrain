Module 02 — Compiler Syntax Trees & Data Handling

Source Code as Data: UTF-8 Bytes, Tree-sitter & Parent-Child ASTs

Tier 1: Beginner Intuition — Why 500-Character Chunking Breaks Code

Never Chop a Recipe in Half Without the Ingredient List

If you split a Python file every 500 characters, you cut functions mid-loop. Even worse, if the LLM retrieves lines 120–145 of src/billing/ledger.py, it cannot see lines 1–18 (where Decimal and InvoiceRequest were imported) or line 25 (where self.tax_rate was initialized on the class).

RepoBrain uses Tree-sitter to parse code into a real syntax tree and splits every file into a linked Parent-Child pair:

  • ASTParentNode (1 per file): Captures top-level imports_header and enclosing_scope (class signatures and attributes).
  • ASTChildNode (1 per function, method, or data model): Captures the exact callable or schema (`node_kind` $\in$ `{"callable", "method", "type_definition"}`). When a Child Node matches a search, RepoBrain automatically packages it inside its Parent Node's imports and class header!
Tier 2: Under the Hood — The UTF-8 Byte Offset vs. Character Index Trap

Why Multi-Byte Characters (€, →, ≤) Corrupt Naive String Slicing

Tree-sitter parses raw C byte buffers and returns node.start_byte and node.end_byte. In UTF-8 encoding:

  • Standard ASCII letters (a-z, 0-9) use 1 byte per character.
  • Currency and math symbols (€, →, ≤) use 3 bytes per character.
  • Emojis (🚀) use 4 bytes per character.

If a docstring contains # Returns € amount → total ≤ max, those three symbols add +6 extra bytes compared to the Python string character count! If you slice source_str[start_byte:end_byte], every function below that docstring is shifted by 6 characters, slicing off the end of your code. RepoBrain always slices raw bytes: source_bytes[node.start_byte:node.end_byte].decode("utf-8").

Module 03 — Semantic Vector Space & Graph Indexing

Embeddings, Cosine Distance (<=>) & pgvector HNSW Graphs

Tier 1: Beginner Intuition — GPS Coordinates for Code Meaning

How Does a Database Know That "Rollback" Means "Restore Snapshot"?

An embedding model (`nomic-ai/nomic-embed-text-v1.5`) reads a function's name, signature, docstring, and body, and converts its semantic meaning into a list of 768 numbers (a unit vector on a 768-dimensional sphere).

Even when a developer searches using completely different words than the code author used (e.g., searching "undo broken file changes" when the method is named BoundedHarnessState.rollback()), their 768-number vectors point in almost the exact same angle!

Tier 2: Under the Hood — Cosine Distance & HNSW Highway Graphs

Searching Tens of Thousands of AST Nodes in Milliseconds

Because our vectors are L2-normalized (`normalize_embeddings=True`), Cosine Similarity is just the dot product of two vectors ($\cos(\theta) = \mathbf{A} \cdot \mathbf{B} \in [-1, 1]$), and `pgvector`'s Cosine Distance operator (<=>) is simply: 

Cosine_Distance(A, B) = 1.0 - Cosine_Similarity(A, B)   (Range: 0.0 = identical to 2.0 = opposite)

To avoid scanning every row in PostgreSQL, we create an HNSW (Hierarchical Navigable Small World) index with m = 16 (bi-directional links per node) and ef_construction = 64 (candidate list depth during graph build). HNSW builds a multi-layer skip-graph: queries enter at the sparse top highway layer (Layer 2), make giant leaps toward the target region, and drop down to Layer 0 to pull the exact Top 40 semantic candidates.

Module 04 — Curing Alphanumeric Blindness

Lexical Full-Text Search (GIN) & Code Identifier Normalization

Tier 1: Beginner Intuition — The Book-Back Index for Exact Symbols

Why Dense Vectors Fail on getUserById vs. updateUserById

Dense embeddings blur exact characters together. If you ask for settleInvoiceById, a pure vector search might rank getInvoiceById higher because both deal with invoices.

PostgreSQL's GIN (Generalized Inverted Index) works like the index at the back of a textbook: it maps every word token directly to the exact `child_id` rows that contain it, assigning highest priority to matches in the function name (Weight A: 1.0), then signature (Weight B: 0.4), docstring (Weight C: 0.2), and body (Weight D: 0.1).

Tier 3: SQL Engineering — Fixing PostgreSQL's camelCase Blindspot

By default, PostgreSQL's `'simple'` parser treats settleInvoiceById as one giant word: settleinvoicebyid. If someone searches "settle invoice", it returns zero results! RepoBrain's immutable SQL function normalize_code_identifiers() emits both the exact symbol and its split sub-tokens: 

CREATE OR REPLACE FUNCTION normalize_code_identifiers(input_text TEXT)
RETURNS TEXT LANGUAGE sql IMMUTABLE PARALLEL SAFE AS $$
    SELECT lower(
         coalesce(input_text, '') || ' ' ||
        regexp_replace(
            regexp_replace(
                regexp_replace(coalesce(input_text, ''), '([A-Z]+)([A-Z][a-z])', '\1 \2', 'g'),
                '([a-z0-9])([A-Z])', '\1 \2', 'g'
            ),
            '[_./:\-]+', ' ', 'g'
        )
    );
$$;

Module 05 — Two-Stage Retrieval Funnel & Ranking Math

Reciprocal Rank Fusion (RRF, k=60) & Cross-Encoder Reranking

Tier 1: Beginner Intuition — Combining Two Different Leaderboards

How Do You Merge Cosine Distance (0.14) with Keyword Score (0.88)?

You cannot add raw vector distances and keyword scores together because their mathematical distributions are completely different. Instead, Reciprocal Rank Fusion (RRF) looks only at where each item placed on its leaderboard (Rank #1, Rank #2, Rank #3...): 

RRF_Score(node) = 1 / (60 + rank_dense) + 1 / (60 + rank_sparse)

An AST node that ranks well in both semantic meaning AND exact keyword matching gets a massive boost over a noisy candidate that only scored well on one side!

Tier 4: CTO Guardrail #5 — Why SQL Must Return a 25-Item Pool for the Cross-Encoder

A Bi-Encoder embeds the query and the code separately, so it cannot see fine-grained token interactions (like whether a variable is being read or mutated). However, running a Cross-Encoder (`cross-encoder/ms-marco-MiniLM-L-6-v2`) on 50,000 rows in a database would take 30 seconds.

RepoBrain uses a Two-Stage Funnel: PostgreSQL narrows 50,000 nodes down to the Top 25 RRF candidates in 5 milliseconds (`LIMIT 25`). Then, the local CPU Cross-Encoder reads those 25 `(query, code)` pairs side-by-side in 35 milliseconds and slices the final top_k = 5.

Compounding Intelligence: Episodic Bug Memory & Corrective Research RAG

1. Self-Correcting Episodic Memory (`project_episodes`)

Growing Smarter Every Time a Test Fails and Heals

In our upgraded architecture, RepoBrain doesn't just index static code—it indexes engineering experience. Whenever `apply_git_patch` fails on Attempt 1 (e.g., a `Decimal` precision mismatch or an unawaited coroutine) and passes on Attempt 2 or 3, an errand worker model automatically distills the episode into PostgreSQL:

  • `root_cause_lesson`:** A concise 1-sentence engineering rule (e.g., "Always quantize Decimal outputs to 0.01 with ROUND_HALF_UP before returning InvoiceResponse").
  • `passing_diff`:** The exact unified diff that turned `exit_code = 1` into `exit_code = 0`.

The next time `search_codebase()` pulls a symbol with a matching error or domain vector, it attaches a compact `<past_episodic_fix>` tag. The more projects you build, the fewer retries your coding agent needs!

2. Token-Sparing Domain Research Agent (Corrective RAG / CRAG)

How We Cut 90% of Documentation Research Tokens

Mindless agentic web browsing is the #1 hidden killer of API budgets. Our `research_technology(query, domain)` tool enforces a strict **Corrective RAG (CRAG)** pipeline:

  1. Local Knowledge Base First: Queries your local pre-indexed library of framework docs, RFCs, and past distilled markdown files (`.repobrain/kb/`).
  2. Deterministic Relevance Gate: A fast local/cheap model scores whether the retrieved local chunks answer the question ($\ge 0.75$). If yes, 0 external search tokens are spent.

Module 09 — Protocol Hygiene & Non-Destructive Self-Healing

FastMCP stdio JSON-RPC Internals & The 3-Retry Surgical Rollback

1. Why `sys.stdout` Must Be 100% Pure JSON-RPC (Guardrail #8)

FastMCP communicates with your IDE over OS pipes (`sys.stdin` for requests, `sys.stdout` for responses). If any library prints a non-JSON string—such as a HuggingFace download bar (`Downloading: 100%`) or a `print("debug")` statement—to `stdout`, the IDE's JSON-RPC parser immediately crashes. RepoBrain locks `TOKENIZERS_PARALLELISM="false"`, `HF_HUB_DISABLE_PROGRESS_BARS="1"`, and routes all Python `logging` strictly to `sys.stderr`.

2. Why `git reset --hard` Is Forbidden & How Surgical Byte Snapshots Work (Guardrail #7)

If you have uncommitted notes in src/uncommitted_notes.py while the agent is fixing src/billing/ledger.py, running git reset --hard on Retry #3 failure would permanently wipe out your uncommitted notes!

Instead, RepoBrain's BoundedHarnessState tracks a per-task TaskCheckpoint keyed by task_id:

  1. Validates diff syntax with git apply --check --whitespace=nowarn - (if this fails, patch_applied=False and iteration is not incremented).
  2. Snapshots the raw bytes of only the target files listed in +++ b/<path> into memory (or records None if the file is newly created by the patch).
  3. Applies the patch and immediately calls retriever.sync_file_if_changed() so PostgreSQL has the new AST line numbers before Retry #2.
  4. Runs pytest or vitest inside our network-disabled, read-only container (--network=none --read-only --tmpfs /tmp:rw,exec,nosuid) and strips site-packages/ and node_modules/ frames.
  5. If Attempt #3 fails, restores the exact pre-task bytes of the touched files, re-syncs PostgreSQL, and leaves src/uncommitted_notes.py 100% intact.

Module 11 — Principal AI Systems Engineer Self-Test

8-Question CTO Architecture & Interview Defense Check

1. Why must `ast_chunker.py` slice `source_bytes[node.start_byte:node.end_byte].decode("utf-8")` instead of slicing the decoded Python string?

Tree-sitter reports offsets in raw UTF-8 bytes. Characters like €, →, and ≤ take 3 bytes (and emojis take 4 bytes) while counting as only 1 Python character. Slicing a Python string with byte indices shifts every subsequent function boundary and truncates code.

2. Why do we unwrap `decorated_definition` and index zero-method classes as `node_kind="type_definition"`?

Unwrapping decorated_definition preserves route URLs and tool decorators (like @router.post() or @mcp.tool()) inside the Child Node. Indexing zero-method classes/interfaces as type_definition ensures Pydantic BaseModel and TypeScript interface contracts are searchable.

3. How does `normalize_code_identifiers()` cure Alphanumeric Blindness in PostgreSQL Full-Text Search?

PostgreSQL's default 'simple' dictionary turns settleInvoiceById into a single token settleinvoicebyid, which fails on partial searches like "settle invoice". Our regex normalizer emits both the exact identifier and its split sub-tokens (settleinvoicebyid settle invoice by id).

4. Why does our lexical query join tokens with disjunction (`|`) and rank with `ts_rank_cd(..., 32)`?

Strict boolean AND (&) collapses to 0 rows whenever a natural-language query includes conversational words (like "in" or "bug") not present in the function tokens. Disjunction (|) retrieves candidates matching any token, while flag 32 normalizes rank via rank / (rank + 1) into [0.0, 1.0).

5. Why do we fuse rankings with RRF ($k=60$) into `LIMIT 25` before running the Cross-Encoder?

Cosine distance ($\in [0, 2]$) and lexical ts_rank_cd operate on incompatible scales, so RRF merges their rank positions without calibration drift. Fetching a 25-item RRF pool gives the Cross-Encoder (ms-marco-MiniLM-L-6-v2) enough recall to perform full cross-attention scoring before slicing the final top_k = 5.

6. Why does `apply_git_patch` call `sync_file_if_changed()` immediately after applying a patch and after rolling back?

If Attempt #1 adds 4 lines to a file and fails the test suite, the AST line numbers on disk have shifted. Recomputing the Git blob SHA (sha1("blob " + len + "\0" + bytes)) and upserting the modified file in PostgreSQL guarantees Attempt #2 never reads stale line numbers.

7. Why is `git reset --hard` forbidden in `BoundedHarnessState.rollback()`?

git reset --hard wipes out all uncommitted developer changes across the entire repository and leaves untracked patch files behind. Per-task byte snapshots in TaskCheckpoint restore or unlink only the specific files touched by that task.

8. How do the Chief Lead Tier and Errand Worker Tier work together to minimize token spend?

Local CPU models handle embeddings and Cross-Encoder reranking at $0 cost, while cheap/local worker LLMs fold >150-line AST chunks, distill Fail-to-Pass test transitions into project_episodes, and compact web docs into cached markdown—leaving the frontier model (Claude Code / Codex / Antigravity) to process only tiny, high-signal context blocks.
Module 12 • Evaluator-Driven State Graphs & Self-Correction

LangGraph CRAG Engine: Bounded Corrective RAG with State Graphs

Architecture Blueprint

Why Linear RAG Fails in Production Software Engineering

Traditional RAG pipelines are linear: Query → Retrieve Docs → Inject Context → LLM Generate. In real-world software engineering, this naive pipeline causes two catastrophic failure modes:

  • Context Pollution: Inaccurate or noisy documentation flooded into the prompt distracts the model from the actual codebase AST.
  • Hallucinated APIs: When local documentation is sparse or missing, standard RAG retrieves irrelevant text that looks superficially similar, causing the LLM to invent nonexistent methods.

RepoBrain resolves this with a 5-Phase Corrective RAG (CRAG) StateGraph implemented in src/repobrain/research_brain.py. CRAG introduces an active Retrieval Grader between retrieval and synthesis:

CRAG State Schema & LangGraph Topology (src/repobrain/research_brain.py) Python 3.14 + LangGraph 
class CRAGState(TypedDict):
    query: str
    domain: str
    slug: str
    local_chunks: List[TechKnowledgeChunk]
    confidence_score: float           # Continuous relevance score [0.0, 1.0]
    grade_verdict: Literal["CORRECT", "AMBIGUOUS", "INCORRECT"]
    web_passages: List[str]            # Strictly < 1,000 tokens dense snippets
    brief: Optional[ResearchBrief]    # Final synthesized brief

# LangGraph StateGraph Assembly with Conditional Edge Routing
builder = StateGraph(CRAGState)
builder.add_node("check_cache", _node_check_cache)
builder.add_node("retrieve_local_kb", _node_retrieve_local_kb)
builder.add_node("grade_retrieval", _node_grade_retrieval)
builder.add_node("bounded_web_compactor", _node_bounded_web_compactor)
builder.add_node("synthesize_and_cache", _node_synthesize_and_cache)

# Routing Rule: If confidence >= 0.75, bypass web search (0 external tokens!)
def route_after_grading(state: CRAGState) -> str:
    if state.get("confidence_score", 0.0) >= 0.75:
        return "synthesize_and_cache"
    return "bounded_web_compactor"

The 0-Token Fastpath & Bounded 1-Hop Compactor

Notice the two extreme optimizations that protect your token budget:

  • Phase 1 Fastpath: On query entry, RepoBrain hashes the query into a filesystem slug (e.g. fastapi_lifespan_state). If .repobrain/kb_cache/<slug>.md exists, the StateGraph short-circuits directly to END in < 5ms at 0 token cost.

Module 13 • Compounding Developer Intelligence

The 3-Tier Self-Learning Loop: Building Software That Learns From Work

Staff Engineer Mental Model

Why Codebases Degrade vs. How RepoBrain Compounds

In typical software teams, codebases suffer from entropy: as more features are added, edge-case bugs recur, new engineers repeat past mistakes, and architectural conventions erode. AI coding assistants usually accelerate this degradation because they are completely amnesiac across chat sessions.

RepoBrain implements an inverted dynamic: The more you use it for work, the more domain expertise it gains.

The 3 Compounding Tiers

From Bug Fix to Permanent Architectural Law

  1. Tier 1: Instant Micro-Immunization (`project_episodes`)
    Whenever a test transitions from failure on Attempt 1 to passing on Attempt 2 or 3, RepoBrain distills (error_signature, target_symbol, root_cause_summary, resolution_diff). Future queries touching that symbol immediately receive the fix before code generation begins.
  2. Tier 2: Macro ADR Auto-Promotion (`.repobrain/kb/adrs/`)
    When the same root-cause pattern recurs ≥ 3 times across different files (e.g. Decimal scale truncation, async route parameter awaiting, or unhandled nulls), RepoBrain clusters the episodes and automatically drafts an Architectural Decision Record (ADR). Architectural Invariants

Guardrail #8 stdio Protocol Hygiene & Multi-Agent Compounding

In production multi-agent environments where Google Antigravity and Claude Code operate simultaneously:

  • stdio Hygiene: The MCP JSON-RPC protocol relies strictly on sys.stdout. Any print() statement corrupts JSON-RPC framing. RepoBrain strictly enforces sys.stderr logging and disables tokenizer progress bars.
  • Shared Episodic Store: Both agents read from and append to .repobrain/episodes.json. When Claude Code discovers a subtle bug resolution in terminal mode, Antigravity instantly receives that solution in its next architectural query.
